# PCP 0.4.2 — outbound media through AstrBot

The broker requests OpenClaw's opt-in inline-media HTTP response. OpenClaw
normalizes MEDIA directives and structured media payloads, reads attachments
through its native guarded loader, and permits local paths only inside the
selected agent's workspace. Public remote URLs use OpenClaw's SSRF checks.
No gateway token, local path or filesystem mount is handed to AstrBot.

PCP validates the content type and records outgoing attachments against the
assistant message before releasing the exact stored bytes to the relay. Images
are metadata-stripped JPEG/PNG/GIF; supported audio/video containers retain their
bytes. Four files and six MiB total per reply. SVG and arbitrary files are not
accepted. Media-only responses are valid. If storage fails, the bridge returns
an explicit failure rather than claiming the attachment was sent.

The AstrBot provider returns an actual MessageChain containing Plain/Image/
Record/Video components. Images and audio use OneBot's supported base64 transport;
video uses AstrBot's native Video component. Existing wake, routing, moderation,
streaming and group policy remain in place. Never send by treating MEDIA text
as the image itself.

The plugin wraps the event's actual send operation, because AstrBot's after-send
hook also runs after caught send errors. It signs an idempotent receipt back to
PCP: broker.media.adapter_accepted or broker.media.failed. Prepared media and
adapter acceptance are distinct; neither asserts that a recipient displayed it.
Missing or invalid attachments produce explicit errors without exposing private
paths. Runtime artifacts remain in the existing host-backed PCP blob storage.

Requires the OpenClaw inline media gateway patch and AstrBot relay plugin 0.3.0.
Older text-only OpenClaw clients are unchanged unless they opt in with
X-OpenClaw-Media: inline. The broker remains the credential/recording boundary;
it does not mount the agent's workspace or create public download links.
