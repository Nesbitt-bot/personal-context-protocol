# v0.2.0

Identity phase 1 (see `docs/auth-oidc.md`).

- Human sign-in with Casdoor OIDC: authorization code flow with state, nonce
  and PKCE (S256); ID tokens verified against the issuer JWKS (asymmetric
  algorithms only), issuer, audience, expiry and nonce. Sign-in requires
  `PCP_OIDC_REQUIRED_GROUP`; `PCP_OIDC_ADMIN_GROUP` members are admins. Missing
  configuration disables sign-in.
- Server-side browser sessions (hashed ids, 12 h), regenerated at login,
  `__Host-` HttpOnly/Secure/SameSite=Lax cookies, CSRF header on writes.
- Session ownership: `owner_user_id`, `principal`, `class` on sessions. Admins
  see all sessions; other members see owned or principal-linked sessions;
  unowned and group sessions are admin-only (403 otherwise).
- Identity claims: single-use, 15-minute, hashed, rate-limited claim codes and
  a `/claim` page that link a platform principal to the signed-in user.
- The single admin-token UI login is now a break-glass path, disabled unless
  `PCP_BREAK_GLASS_ADMIN_LOGIN=1`. Agent recording tokens, recording URLs and
  scoped manager tokens are unchanged.
- Migration 011 (additive, idempotent). Existing sessions become unowned
  (admin-only) until claimed.
- Compose passes the OIDC variables to the app and publishes on loopback by
  default; `thirdparty/` (future channel plugins) is excluded from the image.
