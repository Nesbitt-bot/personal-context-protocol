# v0.1.14 — URL routing, scroll fixes, trash model (2026-06-25)

## Highlights

- **URL-driven session routing**: clicking a session pushes `/dashboard?session=<id>`
  to the URL bar, making every session shareable with the sidebar always visible.
  The standalone `/sessions/[id]` page redirects to the dashboard.
- **Trash model**: archive is now "move to trash". A Trash section in the nav shows
  archived items with Restore / Delete permanently options. Empty Trash permanently
  deletes all archived topics and sessions. New `DELETE` endpoints for permanent
  deletion of sessions and topics; topic archive now accepts `{archived: false}` to
  restore.
- **Drag-to-move sessions**: drag a session onto a topic group to move it there.
  Topic expands automatically on hover.
- **Collapsible events panel**: a toggle button on the right edge shows/hides the
  events sidebar. Defaults to hidden.
- **Scroll fixes**: the messages column is properly constrained with
  `h-[calc(100vh-57px)] overflow-hidden` plus `flex-1 overflow-y-auto`, fixing
  the long-message overflow bug. A "Latest messages" button appears when scrolled
  up past 3 messages and scrolls to the bottom on click.
- **Topic dropdown**: only non-archived topics appear in the session edit menu.

## Upgrade notes

- Existing archived sessions and topics appear in the new Trash section.
- The `POST /api/v1/topics/:id/archive` endpoint now accepts `{ "archived": false }`
  for restoration. The previous behavior (no body = archive) is unchanged.
- `DELETE /api/v1/sessions/:id` and `DELETE /api/v1/topics/:id` are new.
- `POST /api/v1/trash/empty` permanently deletes all archived items.

# v0.1.13 — Agent read-messages endpoint + full-history instruction (2026-06-25)

## Highlights

- Fixed the root cause of agents failing to record context: the protocol descriptor's
  `review` route pointed to the admin endpoint (UI-token only). Agents could not read
  their session's past messages with an access token.
- New `GET /api/v1/agent/sessions/:id/review` (access-token scoped) returns all
  messages already recorded, so the agent knows the full conversation history.
- Protocol descriptor now exposes `read_messages` route + `existing_message_count`
  + `hint` telling the agent where to pick up.
- Instruction explicitly tells agents to record **ALL** messages — full history,
  not just the current exchange.

## Upgrade notes

- After deploy, agents will see `read_messages` in the protocol, fetch it, and
  record the full conversation from the correct ordinal.
- No schema changes.
