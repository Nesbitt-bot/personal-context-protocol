# PCP 0.4.0 — AstrBot execution and image history

Verified owner DMs can reach an OpenClaw execution agent through the existing
signed broker. Every non-PCP tool call requires a fresh server authorization:
live delegated grant, matching agent, current linked administrator or selected
group sender, and a tool in the private operator policy. Removing access takes
effect on the next tool call. Groups start empty and retain group-only context.

The agent dashboard `/adapters` owns the access list editor. Its private policy
directory is shared read-only with PCP. Each enabled group requires a separate
sandboxed agent; it cannot reuse the owner's agent. No group is enabled by this
release. Native channel permissions and ordinary HTTP restrictions are preserved.

AstrBot image segments are fetched with limits from platform CDNs or its local
temporary directory. Up to four images, six MiB total, are signed with the turn.
PCP checks the real format and decoded size, strips metadata, and converts to
WebP while retaining animation. Sanitized images reach OpenClaw's vision input
and are attached to the existing PCP message. Native OpenClaw inline images
use the same storage through the durable sync queue (64 MiB queue bound).

Migration 015 stores attachment metadata; bytes live in `DockerVolumes/pcp/blobs`.
Private image delivery uses normal Casdoor session authorization on every request,
including public sessions. Images have no public blob URL. The UI displays images
inside their message. Replays use session/external attachment keys and reject
different source bytes for the same key; duplicate content shares a blob.

Required runtime settings: `PCP_BLOB_DIR=/app/blobs`,
`PCP_EXECUTION_POLICY_FILE=/run/pcp-adapters/execution-policy.json`. Compose
binds existing host directories and refuses to create them silently. Back up
the blobs alongside the PostgreSQL dump; preserve both during rollback.

Optional nginx config: `deploy/nginx/pcp.conf` caches only immutable application
assets and serves protected image bytes through an internal X-Accel location
after PCP authorization. Set `PCP_MEDIA_ACCEL=1` only with that proxy installed.

This release supports images/GIFs. Document/audio/video ingestion, historical
media backfill, OCR, resumable uploads and retention/garbage collection remain
in the media roadmap. Raw originals are not retained by PCP. Native retry queues
contain private source images until upload; keep their existing private mount.
