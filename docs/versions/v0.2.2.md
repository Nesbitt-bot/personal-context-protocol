# v0.2.2

Cross-machine projects, a sync conflict policy, and web UI fixes.

- **Fix: dialogs** (token manager, session tokens, token display, create
  topic/session). The global token manager was rendered inside the sticky top
  nav, whose `backdrop-filter` makes it the containing block for `position:
  fixed` children: the overlay was only as tall as the nav and the centred
  panel sat above the top of the screen, so its close button and form were
  unreachable. All dialogs now share `src/components/modal.tsx`: rendered in a
  portal on `document.body`, `role="dialog"` + `aria-modal`, capped to the
  viewport and scrolling inside, focus moved in and trapped, Esc and Close
  work everywhere (the token display had no Esc), focus returns to the opener.
- **Fix: navigation.** Signed-in users get **Sessions** and **Projects** in the
  top nav (Tokens and Settings stay admin-only); on phones every entry is in a
  menu (Tokens and Settings were unreachable below 640 px). The signed-in home
  page offers "Open sessions" instead of the login portal, `/login` sends an
  already signed-in user on to `next`, and the break-glass login now uses the
  same return-path check as the server (a `/\host` path was accepted).
- **Projects** (migration 013, additive): `projects` keyed like the OpenCode
  session-manager (`git:<host/owner/repo>` or `name:<basename>`), explicit
  `project_aliases`, `project_workspaces` per machine (OpenClaw container,
  Linux host, remote Linux, Windows, macOS), `sessions.project_id` with a
  per-task context title and summary. Project list and detail pages with
  start-dev snippets per machine and the sessions grouped by project.
- **APIs for plugins** (global scoped token with the new `manage_projects`
  flag, never admin): resolve a project by remote or workspace directory,
  register a project and workspace, attach session context, append-only
  message merge, AI merge tasks.
- **Sync conflict policy**: last writer wins by plugin timestamp with a
  future-clock guard, losing edits of titles/summaries kept in
  `sync_conflicts` for review, "Request AI merge" stores a pending task for an
  agent (PCP never calls a model). See `docs/protocol.md`.
- **Reorganization tool**: `thirdparty/pcp-session-import/organize-projects.mjs`
  (dry run by default; apply only adds) and a read-only
  `pcp-operator.js sessions export`. See `docs/projects.md`.
